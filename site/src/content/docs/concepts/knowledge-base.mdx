The Knowledge Base is the set of documents that records what your project is and how it works, which AID agents read before they change anything.

It lives in `.aid/knowledge/` and outlives any one session or work. A new teammate, human or AI, reads it and gets the project's current shape. The [glossary entry for the Knowledge Base](/reference/glossary/#knowledge-base) gives the short definition.

## What it holds

<KbStructure />

- **The project card.** `PROJECT.md` is a one-page card: what the project is, its stack, how to build and test it, where things live and the rules that never bend. It is optional. AID ships a template for it, and you write it yourself.
- **Documents.** One file per topic, such as `architecture.md`, `coding-standards.md` and `test-landscape.md`. The full standard list, with a template for each, is on the [Knowledge Base documents page](/reference/kb/).
- **Meta-documents.** `INDEX.md` gives each document a short summary. `README.md` tracks which documents are complete. `STATE.md` holds the discovery grade and the open questions.
- **The file inventory.** `project-index.md` is a scan of your files that discovery builds before its writers start. It lives in `.aid/generated/`, outside the Knowledge Base.
- **Extensions.** Documents that only your project needs, added when you confirm the document set.

## How it gets built

On a project that already has code, you run `/aid-discover`. It asks you to confirm the project's domain, proposes the documents that fit that domain, and waits for you to confirm or edit the list. It then writes the documents, reviews and grades them, and fixes what the review finds. You approve the result at the end. A fresh project has no code to scan, so you start with `/aid-describe`, which updates `INDEX.md` and `README.md` as the requirements take shape.

The chosen list is the [declared doc-set](/reference/glossary/#declared-doc-set). Because each document type has a fixed file name, a skill that needs schemas always reads `schemas.md`, and one that needs debt always reads `tech-debt.md`. A small project can leave some documents thin. The shape stays the same.

Discovery does not guess. When it cannot ground a fact in your files, it records a question in `STATE.md` and asks you before it approves the Knowledge Base.

## How you keep it current

The Knowledge Base changes as your project does. Two skills maintain it.

- `/aid-update-kb` applies one targeted change that you confirm, in its own worktree.
- `/aid-housekeep` re-syncs a Knowledge Base that has drifted from the code, then clears stale work artifacts.

The [pipeline page](/concepts/pipeline/) shows where these sit among the phases.

## How agents find what they need

AID does not use embeddings or a vector database. An agent finds knowledge through plain files: a fixed name for each document, and an index. It loads the least that answers its question.

<ContextLoading />

1. **The project card, first.** An agent reads `PROJECT.md` first, when the project has one.
2. **The index, to find a document.** It opens `INDEX.md` only to find a specific document, not to read everything.
3. **One document, on demand.** It loads the single document a task needs, not the whole Knowledge Base.

A document names the source of a claim with a file path plus a heading or a searchable string, never a line number, because line numbers drift on the next edit. A lint script checks this rule.

Reviewers use the Knowledge Base too: they judge work against its conventions. See [Agents](/concepts/agents/) for who reviews what.
