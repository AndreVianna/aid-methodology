This page explains how AID gives each agent a model tier and how skills dispatch agents to do their work.

An agent is a specialist that a skill hands one job to. For the list of agents, with each one's role, tools and default tier, see the [agents reference](/reference/agents/). This page covers the rules behind it.

## Model tiers

<AgentTiers />

Each agent definition names a default tier in its `tier:` line. That is the size of model the agent gets unless a dispatch chooses otherwise. The tier is a default, not a ceiling.

The rules for choosing come from one shared rubric, [the agent dispatch tiering rules](https://github.com/AndreVianna/aid-methodology/blob/master/canonical/aid/templates/agent-dispatch-tiering.md). It sets two levers from the difficulty of the task:

- **Model tier.** Large, medium or small.
- **Reasoning effort.** How hard the model thinks. Effort is a separate lever, and the rubric says tuning it is often better than switching tiers.

The rubric defaults low and escalates only for the hard cases. Routine work runs on medium at medium effort. Retrieval-heavy work, such as research or Knowledge Base writing, runs on medium at low effort, because deeper thinking does not help retrieval. Mechanical work runs on small. Hard and frontier work moves to large.

On the Codex tool, the effort is fixed per tier in the tool's profile. On Claude Code, Cursor and GitHub Copilot CLI, the skill that dispatches the agent sets the effort. The Antigravity profile renders no effort field, so the table below gives it a model per tier only.

## Who reviews the work

An agent that writes does not grade its own work. A separate reviewer agent, in a clean context, checks the output against the task's criteria.

The reviewer's tier follows the work. When a task is hard, its executor and the reviewer of that output move to the higher tier together, and a reviewer of a large-tier executor's output runs on the large tier. The tier affects the quality of the findings, not the grade, because the grade comes from a script and not from the model.

During `/aid-execute`, these reviews work differently:

- The quick check after each task runs on the small tier. It looks for serious problems and does not grade.
- The delivery gate reviews the whole delivery. Its tier follows a complexity score of the delivery: small for a low score, medium for a middle score and large for a high one. The score counts tasks, dependency depth, risky task types and specialist consults.

## How skills dispatch agents

A skill with a state machine has a Dispatch table. Each row is one state of the skill, and it names the worker for that state: an agent, or `inline` when the skill does the step itself. A simpler skill dispatches its agent in plain steps instead. `/aid-review`, for example, dispatches `aid-reviewer` once, in a clean context. Examples of Dispatch tables:

- `/aid-discover` hands GENERATE and FIX to `aid-architect`, REVIEW to `aid-reviewer`, and runs ELICIT, Q-AND-A and APPROVAL inline.
- `/aid-specify` hands INITIALIZE and CONTINUE to `aid-architect` and REVIEW to `aid-reviewer`.
- `/aid-update-kb` sends ANALYZE to `aid-researcher` and SCOPE to `aid-architect`, each in a clean context that does not see the conversation so far.
- `/aid-execute` runs the quick check with `aid-reviewer` at the small tier.

The skill pages under [Skills](/skills/) show what each skill does. While a dispatched agent runs, the skill reports progress so you can see that it is still working.
