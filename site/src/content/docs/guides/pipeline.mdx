This page shows you how to run a piece of work through the AID phases, from /aid-config to /aid-execute, and which command to run at each step.

## Before you start

This page gives the steps. Install AID and add it to your project first. The [Installation guide](/guides/installation/) shows how.

To learn why the phases exist, read the [pipeline concept page](/concepts/pipeline/). This guide only names the command and the result of each step.

## The pipeline at a glance

The [pipeline concept page](/concepts/pipeline/) has the full diagram, with a text version of every step.

There are three ways in:

- A [shortcut](/reference/glossary/#shortcut), such as `/aid-fix`, when you know the kind of change.
- [`/aid-triage`](/reference/glossary/#aid-triage), when you are not sure which skill fits. It suggests a step and writes nothing.
- `/aid-describe`, for broad work or a new project.

A project that already has code ([brownfield](/reference/glossary/#brownfield)) runs `/aid-discover` first. A new project ([greenfield](/reference/glossary/#greenfield)) goes from `/aid-config` straight to `/aid-describe`.

A shortcut runs the shared [shortcut engine](/reference/glossary/#shortcut-engine), which does the work of Describe through Detail in one mostly autonomous run. It stops at an approval halt before Execute. `/aid-describe` instead takes each phase through its own [phase gate](/reference/glossary/#phase-gate), where you approve the result.

## Step 0 — Configure (`/aid-config`)

Run `/aid-config` before you start your first piece of work. It shows your project settings, and it copies the settings template to `.aid/settings.yml` on the first run. It is not a numbered phase.

<Steps>
1. **Run the skill.** Type `/aid-config` in your AI tool. It prints all settings.

2. **Change a setting.** Run `/aid-config <key>` to view and update one setting, for example `/aid-config name` or `/aid-config minimum_grade`.
</Steps>

<Aside type="tip">
Run `/aid-config` again whenever you want to look at your settings. The skills that grade, review or dispatch agents read `.aid/settings.yml` (`/aid-triage` and `/aid-chat` do not), so keep it accurate.
</Aside>

## The phases

Each phase is a skill. Run the skill in your AI tool. It works through its steps and produces the result named below.

### Phase 1 — Discover (`/aid-discover`)

**Brownfield projects.** Discover reads your existing code, configuration and documents. It builds the [Knowledge Base](/reference/glossary/#knowledge-base) with what it finds: architecture, conventions and patterns. When the code does not answer a question, it asks you instead of guessing. It grades the documents and fixes them until they meet the minimum grade.

**Result:** documents in `.aid/knowledge/` that describe your project.

<Aside type="note">
A greenfield project has no code to read, so it skips Discover. Start at Phase 2a, Describe.
</Aside>

### Phase 2a — Describe (`/aid-describe`)

Describe interviews you about what you want to build. It adapts its questions to your answers, then writes the requirements.

**Result:** `REQUIREMENTS.md` in a new work folder, `.aid/works/work-NNN-<name>/`.

For a small, well-scoped change, run a shortcut or ask `/aid-triage` instead. See [Small changes with shortcuts](/get-started/lite-path/).

### Phase 2b — Define (`/aid-define`)

Define starts from approved requirements. It splits them into features and cross-checks the result against the Knowledge Base and the code.

**Result:** one `### Feature NNN` section per feature in section 11 of `REQUIREMENTS.md`. Features are sections, not separate files.

### Phase 3 — Specify (`/aid-specify`)

Specify writes the technical specification for one feature, together with you. Name the feature:

```
/aid-specify work-001/feature-001
```

**Result:** a `#### Technical Specification` subsection in that feature's section of `REQUIREMENTS.md`.

Run it once for each feature.

### Phase 4 — Plan (`/aid-plan`)

Plan groups the specified features into deliveries, in an order where each delivery stands on its own.

**Result:** `PLAN.md`, with one `### delivery-NNN` stanza for each delivery, and a `deliveries/delivery-NNN/STATE.yml` file for each one.

### Phase 5 — Detail (`/aid-detail`)

Detail breaks a delivery into small, typed tasks and orders them by dependency. A task has one of eight types: RESEARCH, DESIGN, IMPLEMENT, TEST, DOCUMENT, MIGRATE, REFACTOR or CONFIGURE.

**Result:** a `deliveries/delivery-NNN/tasks/task-NNN/DETAIL.md` file for each task, and an execution graph in `PLAN.md`.

Run it once for each delivery.

### Phase 6 — Execute (`/aid-execute`)

Execute carries out one task by its type and gives it a quick check. The quick check fixes a CRITICAL finding on the spot, once, and defers HIGH findings to the delivery gate. The gate runs the full graded review and the fix loop once the delivery's tasks are done. Name the task:

```
/aid-execute work-001 task-001
```

**Result:** the built task, quick-checked against its acceptance criteria. Code goes on one branch for the delivery, named `aid/<work>-delivery-NNN`. A task that only writes `.aid/` files may skip the branch.

Run it once for each task, in dependency order. If a task depends on one that is not done, Execute stops and lists what is pending.

## Deliver: deploy and monitor (optional)

After Execute, the optional Deliver skills package the work and watch it. You run each one yourself.

### Deploy (`/aid-deploy`)

Deploy packages completed deliveries into a release. It checks the build, packages the release the way your Knowledge Base says to, and writes release notes into a package file in the work folder.

### Monitor (`/aid-monitor`)

Monitor watches the running system, classifies what it finds and routes each finding. A bug goes to `/aid-fix`. A change request goes to `/aid-triage`.

<Aside type="note">
You do not need either Deliver skill to use AID. Many teams run the phases and ship through their own CI/CD pipeline.
</Aside>

## Short path or full path

Not every change needs every phase. For a small, well-scoped change, run the matching shortcut (`/aid-fix`, `/aid-create api` and others), or ask `/aid-triage` which one fits. The shortcut engine writes a flat work folder, and it halts for your approval before `/aid-execute`. [Small changes with shortcuts](/get-started/lite-path/) shows the flow.
