This page shows you how to start the AID web dashboard, follow your projects in a browser and share it on your private tailnet.

## What the dashboard is

The AID web dashboard is a local browser page for the AID projects on your machine. It is not the text status screen that bare `aid` prints in the terminal. You start it yourself, and it runs as a background server.

One dashboard serves every project registered on this machine. It shows:

- A **home page** that lists the registered projects, each with its AID version and a Knowledge Base chip.
- A **project page** with the sections Tools, Knowledge Base, Connectors, External Sources and Pipelines.
- A **task page** with the findings, the review ledger, the raw state file and the logs of one task.
- A **breadcrumb** at the top that shows where you are: Home, then the project, then the pipeline, then the task.

The server listens on `127.0.0.1` only. It does not bind to a public address.

## Start the dashboard

<Steps>

1. **Choose a server runtime.**

   The dashboard ships one server written for Node and one written for Python. Use whichever is installed. The command needs `node` or `python3` on your PATH, and the Python server needs Python 3.11 or later.

   ```bash
   aid dashboard start node
   aid dashboard start python
   ```

2. **Open the URL the command prints.**

   ```
   Dashboard (node) running at http://127.0.0.1:8787 -- stop with: aid dashboard stop
   ```

   Open that URL in your browser. The default port is `8787`.

3. **Use another port if you need one.**

   ```bash
   aid dashboard start node --port 9000
   ```

   The port must be a whole number from `1024` to `65535`.

</Steps>

The dashboard keeps running until you stop it. It works from any directory, because it is not tied to the current project.

<Aside type="note" title="Already running?">
If a dashboard is already running, `aid dashboard start` prints its URL and exits with code `8` without starting a second one. Run `aid dashboard stop` first if you want a different port or runtime.
</Aside>

## Stop the dashboard

```bash
aid dashboard stop
```

Stopping is safe to repeat: it does nothing when the dashboard is not running. It also removes the tailnet exposure if you started the dashboard with `--remote`.

## The home page

The home page lists every project registered on this machine. Open a project to see its page.

A project appears here once it is registered. Running `aid add <tool>` inside a project is one way to get it registered. You can also run `aid projects add` or `aid projects scan`. Run `aid projects list` in a terminal to see the registry. If a registered folder is missing, its card is marked unavailable and shows the `aid projects remove` command that untracks it.

## The project page

The project page is a live view of one project. It refreshes on its own.

### Pipelines

Each work in the project is listed as a pipeline card. The card shows the phase the work is in. Open a card to see the work, then open a task to see its detail. The dashboard also finds works that live on other git worktrees of the project. When the same work appears on more than one worktree, it shows one entry. Each task takes the most advanced state found on any worktree, and the work's own pipeline state comes from the copy with the newest `Updated` value. Tasks and the other lists are combined from all the copies.

### Knowledge Base card

The [Knowledge Base](/reference/glossary/#knowledge-base) card shows one of five states:

| State | Meaning |
|-------|---------|
| **No KB** | There is no Knowledge Base yet. Run `/aid-discover` to build it. |
| **Building** | Discovery is building the Knowledge Base. |
| **Preparing** | The Knowledge Base is approved and its summary is being generated. |
| **Ready** | The Knowledge Base is approved and current. |
| **Outdated** | The branch has moved past the point the Knowledge Base was approved at. Run [`/aid-housekeep`](/reference/glossary/#aid-housekeep) to bring the documents up to date. |

The card also lists any documents marked suspect.

## The task page

Open a task from its pipeline to see the task page. It has four parts:

- **Findings**: what the reviewer found in this task.
- **Review ledger**: the graded review results for the task.
- **Raw STATE.yml**: the raw text of the task's state file, collapsed until you open it.
- **Logs**: the log output captured for the task.

Use the breadcrumb to go back. Each level above the task is a link.

## Changing things from the dashboard

When you start the dashboard on its own machine, it is writable. The page footer says `writable`. From the pages you can register a project, update the CLI, change the minimum grade, add or remove connectors, rename a task and delete a pipeline. When the dashboard is read-only, the footer says `read-only` and these controls are hidden.

## Share the dashboard over a private tailnet

`--remote` exposes the dashboard to other devices on your [Tailscale](https://tailscale.com/) tailnet. It never binds to a public address.

```bash
aid dashboard start node --remote
```

On success, the command prints the local URL and the private one:

```
Dashboard (node) running at http://127.0.0.1:8787 -- stop with: aid dashboard stop
Remote (private): https://your-host.tail12345.ts.net/
```

`aid dashboard stop` removes both the local server and the tailnet exposure.

### Requirements

- Tailscale must be installed on this machine, running and logged in.
- If Tailscale is missing or not running, `--remote` prints an error and exits with code `10`. The local server keeps running at `127.0.0.1`.

### Writes over the tailnet

Under `--remote` the dashboard is read-only. To allow changes from other devices, add `--allow-writes`:

```bash
aid dashboard start node --remote --allow-writes
```

### Limit who can reach it

By default, every device on your tailnet can reach this machine once `--remote` is on. To limit access to your own identity, add a grant like this to your tailnet policy file, on the access-controls page of the Tailscale admin console:

```json
{
  "grants": [
    {
      "src": ["you@example.com"],
      "dst": ["your-host-short-name"],
      "ip": ["tcp:443"]
    }
  ]
}
```

Replace `you@example.com` with your Tailscale login and `your-host-short-name` with this machine's short name. The `--remote` command prints the same guidance to stderr.

<Aside type="caution" title="What people on your tailnet can see">
Anyone you grant access sees the names and paths of all registered projects, plus each project's pipelines, tools and Knowledge Base status. With `--allow-writes` they can also change project state. Grant access only to people you trust with that.
</Aside>
