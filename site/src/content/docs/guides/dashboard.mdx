The dashboard is a web page that runs on your own computer. It shows every AID project you have registered: which works are in progress, how far each task has got, and whether each Knowledge Base is up to date. You use it when the state files are too many to read one by one.

It is separate from the plain text summary you get when you type `aid` with no arguments. You start the dashboard on purpose, and it keeps running in the background until you stop it.

## Start the dashboard

You need either Node.js or Python 3 on your `PATH`. You choose which one runs the server. They show the same pages.

<Steps>

1. Start the server with the runtime you have.

   <Tabs syncKey="runtime">
     <TabItem label="Node.js">

   ```bash
   aid dashboard start node
   ```

     </TabItem>
     <TabItem label="Python">

   ```bash
   aid dashboard start python
   ```

     </TabItem>
   </Tabs>

   You should see one line like this:

   ```text
   Dashboard (node) running at http://127.0.0.1:8787 -- stop with: aid dashboard stop
   ```

2. Open that address in your browser.

   You should see the **Projects** page: one row for each project in your registry.

3. Click a project to open it.

</Steps>

The command works from any folder. It does not belong to the project you are standing in. On Windows, run the same commands in PowerShell or Command Prompt. On Python, the command looks for `python3`.

To use another port, add `--port`. It must be a whole number from 1024 to 65535, and the default is 8787.

```bash
aid dashboard start node --port 9000
```

If a dashboard is already running, `aid dashboard start` prints its address and exits with code 8. Stop it first if you want a different port or runtime.

## Make sure your projects appear

The dashboard lists only registered projects. `aid add` registers a project for you. For a project set up another way, run one of these:

```bash
aid projects add                 # register the current folder
aid projects add /path/to/repo   # register another folder
aid projects scan                # find every folder under your home that has .aid/
aid projects list                # see what is registered
```

See [The aid command](/reference/cli/) for all the options.

## What you see

**Projects page.** Each row is a registered project, with its name, version and tools. A project whose folder has gone missing is shown as unavailable.

**Project page.** Each project has these sections:

| Section | What it shows |
|---|---|
| Pipelines | Every work in the project, with its phase and status, and the tasks inside it. It also finds works that exist only on another git worktree. When the same work differs between branches, it shows the most advanced state. |
| Knowledge Base | A status badge for the project's Knowledge Base, and a link to its rendered page (`kb.html`). |
| Connectors | The ticket-system connectors set up for the project. See [Connectors and tickets](/guides/connectors-and-tickets/). |
| External Sources | Outside documents and sources registered for the project. |
| Tools | The AI tools installed in the project, and their versions. |

The Knowledge Base badge has five values:

| Status | Meaning |
|---|---|
| Pending | `.aid/knowledge/` is missing or empty. |
| Generating | The documents exist but you have not approved them yet. |
| Preparing | The documents are approved, but the rendered page or its summary is not ready. |
| Approved | The Knowledge Base is ready and current. |
| Outdated | It was approved, but your main branch has moved on since. Run `/aid-housekeep` or `/aid-discover` to refresh it. |

Open a task to see its details. For what the underlying files contain, see [Work files](/reference/work-files/). For the Knowledge Base, see the [Knowledge base guide](/guides/knowledge-base/).

## Making changes from the dashboard

On your own machine the dashboard can change things, not only show them. It does this by running the same small helper scripts the skills use. It can:

- edit a task's notes, rename a task or a work, stop or resume a task, mark a work finished, or delete a work
- change project settings (see [Settings and manifest](/reference/settings/))
- add, update or remove a tool in a project
- add or remove a connector or an external source
- add or remove a project from the registry, and update the `aid` CLI

If you do not want changes, do not use these controls. Sharing the dashboard with `--remote` makes it read-only unless you add `--allow-writes`.

## Share it over your private network

`--remote` shares the dashboard with your other devices through [Tailscale](https://tailscale.com/). It never opens a public port.

```bash
aid dashboard start node --remote
```

You should see a second line with a private `https://` address:

```text
Dashboard (node) running at http://127.0.0.1:8787 -- stop with: aid dashboard stop
Remote (private): https://your-host.your-tailnet.ts.net/
```

You need Tailscale installed, running and signed in on this machine. If it is not, the command prints why, exits with code 10, and leaves the local dashboard running on your machine only.

| Flag | What it does |
|---|---|
| `--remote` | Shares the dashboard on your tailnet. It is read-only. |
| `--remote --allow-writes` | Shares it and also lets remote users make the changes listed above. |

<Aside type="caution">
Anyone who can reach this computer on your tailnet can see all registered project names and paths, and each project's state. With `--allow-writes` they can also change them. Limit access in your Tailscale access rules to people you trust.
</Aside>

## Stop the dashboard

```bash
aid dashboard stop
```

You should see `aid: dashboard stopped.` It is safe to run when nothing is running. It also removes any `--remote` sharing.

## If something goes wrong

| What you see | What to do |
|---|---|
| `already running` (exit 8) | Run `aid dashboard stop`, then start again. |
| `node not found` or `python3 not found` (exit 9) | Install that runtime, or start with the other one. |
| `server failed to start` (exit 3) | Read the last lines it prints, or open `~/.aid/.temp/dashboard.log`. The port may be in use, so try `--port`. |
| `--port must be an integer in 1024..65535` (exit 2) | Choose a port in that range. |
| The page opens but a project is missing | Run `aid projects list`, then `aid projects add` in that folder. |
| `server is missing from the install tree` (exit 7) | Run `aid update self` to repair the install. |

The server always listens on `127.0.0.1`, so only programs on your own computer can reach it.
