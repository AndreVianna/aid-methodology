This page shows you how to start your first piece of work in AID and follow it through the pipeline to built code.

Where you start depends on your project. A project that already has code is [brownfield](/reference/glossary/#brownfield), and you start it with `/aid-discover`. A new project with no code is [greenfield](/reference/glossary/#greenfield), and you start it with `/aid-describe`. After that, both follow the same phases, one after another. Each phase ends at a [phase gate](/reference/glossary/#phase-gate), where you review the result and approve it before the next phase begins.

For a small, well-scoped change you do not need every phase. See [Small changes with shortcuts](/get-started/lite-path/).

## Before you start

Install the `aid` command and add AID to your project. The [Install page](/get-started/install/) shows both steps.

Then run this command in your AI tool:

```
/aid-config
```

[`/aid-config`](/reference/glossary/#aid-config) shows your project settings, such as the project name and the minimum grade. On the first run it copies the settings template to `.aid/settings.yml`. Run `/aid-config <key>` to change one setting, for example `/aid-config minimum_grade`.

## Start with an existing project (Brownfield)

1. Run `/aid-config`, as above.
2. Build the [Knowledge Base](/reference/glossary/#knowledge-base), the set of documents that describes your project:

   ```
   /aid-discover
   ```

   Discover reads your code and writes the Knowledge Base to `.aid/knowledge/`. Where the code does not answer a question, it asks you. At the end, it asks you to approve the Knowledge Base.
3. For each piece of work, choose how to start:
   - You know the kind of change: run a [shortcut](/reference/glossary/#shortcut), such as `/aid-fix "login crash on special characters"`.
   - You are not sure: run [`/aid-triage`](/reference/glossary/#aid-triage) with a one-sentence description. It suggests one next step and writes nothing.
   - The work is broad or has several parts: run `/aid-describe`.
   - You only have a question: run [`/aid-ask`](/reference/glossary/#aid-ask).

   The shortcuts are described on [Small changes with shortcuts](/get-started/lite-path/). For broad work, continue with the phases below.
4. When the project drifts from its Knowledge Base, run [`/aid-housekeep`](/reference/glossary/#aid-housekeep). It re-syncs the Knowledge Base and clears stale work files.

## Start a new project (Greenfield)

1. Run `/aid-config`, as above.
2. Run `/aid-describe`:

   ```
   /aid-describe
   ```

   Describe interviews you, one question at a time. Because a greenfield project has no code to read, it also writes a first set of Knowledge Base documents from your answers. They are marked `source: forward-authored`, which means the design is the source of truth and the code is built to match it.
3. Continue with the phases below.
4. As the code grows, run `/aid-housekeep` now and then. It flags places where the code differs from the design and leaves the decision to you. It never overwrites the design on its own.

## Follow the phases

Run the phases in this order: Discover, Describe, Define, Specify, Plan, Detail, Execute. Brownfield work has already done Discover. Each phase is a skill. Read what a phase produced and approve it before you start the next one.

1. **Describe.** `/aid-describe` interviews you and writes `REQUIREMENTS.md` in a new work folder, `.aid/works/work-001-<name>/`. When you approve the requirements, Describe tells you to run `/aid-define`.
2. **Define.** `/aid-define` splits the approved requirements into features. Each feature is a [feature section](/reference/glossary/#feature-section) in section 11 of `REQUIREMENTS.md`.
3. **Specify.** Run this command once for each feature:

   ```
   /aid-specify work-001/feature-001
   ```

   Specify writes the technical specification into that feature's section, together with you. This is where you settle what will be built.
4. **Plan.**

   ```
   /aid-plan
   ```

   Plan groups the features into deliveries and writes them to `PLAN.md`, one [delivery stanza](/reference/glossary/#delivery-stanza) for each. It also creates a `deliveries/delivery-NNN/` folder with a [`STATE.yml`](/reference/glossary/#state-file) for each delivery.
5. **Detail.**

   ```
   /aid-detail
   ```

   Detail breaks a delivery into small, typed tasks. Each task gets a folder `deliveries/delivery-NNN/tasks/task-NNN/` with a [`DETAIL.md`](/reference/glossary/#detailmd) that holds its type, scope and acceptance criteria.
6. **Execute.** Run this command once for each task:

   ```
   /aid-execute work-001 task-001
   ```

   Execute carries out the task by its type, then has it reviewed and fixed until it meets the minimum grade. `work-001` is optional when you have only one work.

If you have more than one work, add the work id to the command, as in `/aid-plan work-001`.

### What each phase produces

| Phase | What you get | Where |
|-------|--------------|-------|
| Discover | The Knowledge Base | `.aid/knowledge/` |
| Describe | `REQUIREMENTS.md` | `.aid/works/work-NNN-name/` |
| Define | Feature sections in `REQUIREMENTS.md` | section 11 of `REQUIREMENTS.md` |
| Specify | A technical specification in each feature section | the same feature section |
| Plan | `PLAN.md` and a `STATE.yml` for each delivery | `.aid/works/work-NNN-name/` and `deliveries/delivery-NNN/` |
| Detail | A `DETAIL.md` for each task | `deliveries/delivery-NNN/tasks/task-NNN/` |
| Execute | The built task, reviewed and graded | your repository |

AID never moves to the next phase without you.

## After the work is built

`/aid-deploy` and `/aid-monitor` are optional. You run each one yourself, after Execute. `/aid-deploy` packages completed deliveries into a release. `/aid-monitor` watches production and routes what it finds to `/aid-fix` or `/aid-triage`.

## Adopt AID one step at a time

You can start small and add steps as you trust the result.

- Run `/aid-discover` alone to build the Knowledge Base, then ask questions with `/aid-ask`.
- Use shortcuts for small changes, as described in [Small changes with shortcuts](/get-started/lite-path/).
- Use the full phases for broad or risky work.
- Add `/aid-deploy` and `/aid-monitor` when you ship regularly.
