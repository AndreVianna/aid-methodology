This page lists the commands, flags, exit codes and environment variables of the [aid CLI](/reference/glossary/#aid-cli), so you can look up how to call it.

To install the CLI, follow the [Installation guide](/guides/installation/).

## Command surface

This is the usage text that `aid -h` prints:

```
aid                              Show the dashboard
aid -h | --help                  Show this help
aid --version | -V               Print the CLI version and exit (same as "aid version")
aid version                      Print the CLI version
aid status                       Show AID state of the current project
aid add <tool>[,...]             Add tool(s) to the current project
aid update [self|all]            Update to latest; inside a project = all tools;
                                    "all" bulk-updates every registered project
aid remove [<tool>... | self]    Remove; no arg = ALL AID from project
aid dashboard start|stop ...     Start/stop the local dashboard
aid projects [list|add|remove|scan]  List/register/unregister/scan AID projects
aid chat <verb> ...              Talk to another AI coding session
aid <command> -h | --help        Per-command help
```

:::note[Bare `aid` is a text screen, not the web dashboard]
Running `aid` with no arguments prints a text screen. It shows the CLI version, the tools installed in the current project, the usage text and, when a newer release exists, an update notice. In a folder with no `.aid/` it prints `no AID project here -- set it up? (aid add)` and exits with code `0`. The help text calls this screen "the dashboard". The browser-based web dashboard is a separate program that you start with `aid dashboard start node` or `aid dashboard start python`.
:::

## Subcommands

### `aid add`

Install one or more AID tools into the current project. The shared skills and runtime are installed once per project. Each tool gets its own agents folder.

```bash
aid add claude-code
aid add codex,cursor                            # several tools at once
aid add claude-code --version 1.1.0             # pin to a release
aid add claude-code --from-bundle ./aid-bundle  # offline: a directory with the shared and tool artifacts
```

With no tool name, `aid add` detects the tool from the current folder: see [Tool auto-detect](#tool-auto-detect). A successful `aid add` registers the project in the projects registry.

### `aid update`

Update the CLI and the installed tools, or update the CLI alone.

```bash
aid update                       # inside a project: the CLI first, then all installed tools
aid update --version 1.1.0       # pin all tools (and the CLI) to a release
aid update self                  # update the aid CLI only
aid update self --dry-run        # print the command it would run, change nothing
aid update all                   # update every registered project
```

- Inside a project, `aid update` moves all installed tools to one version. It takes no per-tool selection.
- Outside a project, `aid update` updates the CLI only.
- `aid update --dry-run` prints the full plan (tools updated, files copied, paths pruned) and exits.
- `aid update all` downloads the tool packages once and applies them to each registered project. It continues past a project that fails, prints a summary at the end, and does not accept `--target`.

`aid update self` detects the install channel and runs the upgrade for it:

| Channel | What `aid update self` does |
|---------|------------------------------|
| `curl`/`irm` bootstrap | Re-runs the bootstrap script (`install.sh` / `install.ps1`) |
| npm | Runs `npm install -g aid-installer@latest` |
| PyPI/pipx | Runs `pipx upgrade aid-installer` |

On Unix, `aid update self` uses `sudo` only when the install location needs root. After the CLI is updated, AID offers to migrate each registered project in turn, answering `All`, `Yes`, `No` or `Cancel`. With no terminal, it skips the migration unless `AID_MIGRATE_YES=1` is set.

### `aid remove`

Remove tools from the current project, or remove the `aid` CLI itself.

```bash
aid remove                       # remove ALL AID from this project (asks to confirm)
aid remove claude-code           # remove one tool
aid remove self                  # remove the aid CLI (asks to confirm)
aid remove self --dry-run        # print the commands it would run, change nothing
```

Removal is manifest-driven: `aid remove` touches only files that `aid add` recorded in `.aid/.aid-manifest.json`. A recorded file that is unchanged is deleted. A recorded file you edited is moved to `.aid/.trash/`. An `AGENTS.md` that differs from what AID wrote is left in place, and the command prints `Left in place (modified or not AID-owned): AGENTS.md`. When the last tool is removed, the project leaves the projects registry.

`aid remove self` is channel-aware: it runs `npm uninstall -g` for the npm channel and `pipx uninstall` for PyPI. For the `curl` channel it removes the install folder and unwires the PATH entry.

### `aid status`

Show the AID install state of the current project.

```bash
aid status
```

Output example:

```
AID 1.2.0  (project: /path/to/your/project)
Installed tools - all at v1.2.0:
  claude-code
  cursor
Shared files: clean
```

- When the installed tools are at different versions, each tool is listed with its own version.
- A tool older than the CLI is marked `(update -> vX.Y.Z)`.
- `Shared files` lists each shared file that changed since install as `modified:`, `missing:` or `extra:`, then prints `Run: aid update (drifted files are moved to .aid/.trash/ first)`.
- Exit code `7` when the folder has a `.aid/` but no AID install. In a folder with no `.aid/`, `aid status` prints `no AID project here -- set it up? (aid add)` and exits with `0`.

### `aid version`

Print the version of the installed `aid` CLI.

```bash
aid version
```

This is the CLI version from the `VERSION` file of the CLI install, not the version of the tools installed in the current project. The project versions are in `.aid/.aid-manifest.json`.

### `aid dashboard`

Start or stop the local web dashboard. It serves every registered AID project and runs from any folder. It is separate from the bare `aid` text screen. For setup and use, see the [Dashboard guide](/guides/dashboard/).

```bash
aid dashboard start node              # start using Node as the server runtime
aid dashboard start python            # start using Python (python3) as the server runtime
aid dashboard start node --port 9000  # use a custom port (default: 8787)
aid dashboard start node --remote     # also expose it over your private tailnet
aid dashboard stop                    # stop the running dashboard
```

**Syntax:**

```
aid dashboard start <node|python> [--remote] [--allow-writes] [--port <n>]
aid dashboard stop
```

| Argument / flag | `start` | `stop` | Description |
|-----------------|:-------:|:------:|-------------|
| `node` \| `python` | required | — | Server runtime. Uses `node` or `python3` from `PATH`. |
| `--port <n>` | optional | — | Listen port on `127.0.0.1`. Integer `1024`–`65535`, default `8787`. |
| `--remote` | optional | — | Also expose the dashboard over a private tailnet (Tailscale). It never binds publicly. |
| `--allow-writes` | optional | — | Opt in to interactive writes. On loopback writes are always enabled, so the flag is accepted but redundant. Under `--remote` the dashboard is read-only unless you also give this flag. |

- The server binds to `127.0.0.1` only.
- `stop` is idempotent, and it also tears down any active `--remote` exposure.
- `--remote` needs Tailscale installed, running and logged in on the host. Otherwise the command fails with an explicit error and the local server keeps running.

Exit codes specific to `dashboard`:

- `8`: the dashboard is already running (run `aid dashboard stop` first).
- `9`: the requested runtime (`node` or `python3`) is not on `PATH`.
- `10`: `--remote` was requested but the tailnet exposure is unavailable.
- `7`: the dashboard server is missing from the install tree (run `aid update` or reinstall).
- `3`: the server failed to start.

### `aid projects`

Manage the set of projects this `aid` installation tracks. The registry stores project paths. It does not install or remove tools.

```bash
aid projects                          # list registered projects (same as list)
aid projects list                     # numbered rows: state, tools, tier; * marks the current folder
aid projects list --verbose           # also print the registry file for each entry
aid projects add                      # register the current folder
aid projects add /path/to/project     # register a specific path
aid projects add --local              # force the user tier
aid projects add --shared             # force the shared tier
aid projects remove                   # unregister the current folder
aid projects remove /path/to/project  # unregister a specific path
aid projects remove 2                 # unregister row 2 of "aid projects list"
aid projects scan                     # crawl $HOME and register every .aid/ project found
aid projects scan --path /path/to/dir # scan only that folder's subtree
aid projects scan --all               # scan the whole machine (Windows fixed drives; Unix from /)
aid projects scan --dry-run           # preview what scan would register; write nothing
```

**Syntax:**

```
aid projects [list] [--local|--shared] [--verbose]
aid projects add  [<path>] [--local|--shared]
aid projects remove [<path>|<N>]
aid projects scan [--path <folder>|--all] [--dry-run] [--depth <n>]
                  [--include-network] [--include-removable] [--local|--shared] [--verbose]
```

`list` prints these columns:

| Column | Values |
|--------|--------|
| `#` | Row number, counted from 1. |
| Marker | `*` = current folder; blank otherwise. |
| `PATH` | Full absolute path. |
| `STATE` | `vX.Y.Z` (tracked), `untracked`, `no-aid` or `missing`. |
| `TOOLS` | Comma-separated installed tool ids. |
| `TIER` | `user` or `shared`. |

- With `--verbose`, each entry is followed by an indented `registry: <file>` line naming the registry file that holds it.
- When the current folder has a `.aid/` but is not registered, `list` ends with a footnote that tells you to run `aid projects add`.
- `aid add`, `aid update`, `aid status` and the bare `aid` screen register the current project when it is not yet in the registry.
- `add` is idempotent. When the folder is not yet an AID project, it creates a bare `.aid/` with no tools installed.
- `remove` accepts a path or a row number `<N>` from `list`. A number below `1` or above the registered count, or a path that is not registered, is an error with exit code `2`. `remove` deletes no files.

Tier is resolved without any prompt. A path under `$HOME` resolves to `user`. A path outside `$HOME` on a global install resolves to `shared`. On a per-user install there is no shared tier: `--shared` prints a notice and uses `user`. Use `--local` or `--shared` to override.

`scan` crawls the filesystem for folders that contain a `.aid/` and registers each one. It is register-only: it never installs, updates or migrates a project, and never writes inside a discovered project's `.aid/`. It reports each project's version, read from the manifest (`untracked` if the `.aid/` has no valid manifest). A project that is already registered is reported and skipped. Once a project is found, its whole subtree, including any nested `.aid/`, is pruned from the scan.

**Directory exclusions.** Before recursing into a folder, `scan` checks whether the folder is itself a project. That check runs first, so a project that happens to be named `build`, `bin` or `.vscode` is still found. Only after that check does `scan` test the folder's name, as an exact, case-insensitive match, against two built-in prune sets:

- **Tier A**: heavy, cache, build, editor and AI-tool directories (`node_modules`, `.git`, `dist`, `build`, `.venv`, `__pycache__`, `.cache`, `.vscode`, `.idea`, `.cursor`, `.claude`, `AppData`, `tmp`, and more). They are pruned at any depth, in every scan mode.
- **Tier B**: OS and system directories (`Windows`, `Program Files`, `ProgramData`, `proc`, `sys`, `dev`, `$Recycle.Bin`, `System Volume Information`, and more). They are pruned only under `--all`, and only as an immediate child of a scanned drive or filesystem root. Tier B is fixed.

**`scan-config.yml`.** You can add your own directory names to Tier A in a `scan-config.yml` that sits beside `registry.yml` in the CLI state home (`$AID_STATE_HOME`, which is `~/.aid` on a per-user install). The file holds a `schema: 1` marker and a `prune_dirs:` list:

```yaml
schema: 1
prune_dirs:
  - node_modules
  - .git
  - my-local-cache
```

- Entries are added to the built-in Tier A set (case-insensitive, without duplicates). The file can only add names. It never removes a built-in name and has no effect on Tier B.
- A missing or unreadable file, or one without `prune_dirs`, is not an error. `scan` then uses the built-in set.
- On the first scan that is not a `--dry-run`, AID seeds the file with the built-in Tier A names if it does not exist. `--dry-run` never creates it, and an existing file is never overwritten.

`scan` flags:

| Flag | Default | Description |
|------|---------|-------------|
| (no scope flag) | — | Scan your home folder (`$HOME` / `%USERPROFILE%`). It enumerates no drives. |
| `--path <folder>` | — | Scan only that folder's subtree. Cannot be combined with `--all`. A `<folder>` that is not a directory is a usage error (exit `2`). |
| `--all` | off | Scan the whole machine. This is the only mode that enumerates drives: Windows local fixed drives (network and removable drives excluded by default), or `/` on Unix. Cannot be combined with `--path`. |
| `--dry-run` | off | Preview what would be registered; write nothing. |
| `--depth <n>` | built-in safety cap | Stop `<n>` levels below each scan root. `<n>` must be a non-negative integer, or it is a usage error (exit `2`). |
| `--include-network` | off | With `--all` on Windows: include network drives. Without `--all` it is a usage error (exit `2`). On Unix it is accepted but has no effect. |
| `--include-removable` | off | With `--all` on Windows: include removable drives. Without `--all` it is a usage error (exit `2`). On Unix it is accepted but has no effect. |
| `--local` / `--shared` | `--local` (forced) | Tier override, with the same meaning as in `aid projects add`. `scan` forces the user tier unless you give `--shared`, so a bulk scan never raises privileges. |
| `--verbose` | off | Print extra per-project and per-root detail. |

### `aid chat`

A channel between AI coding sessions, in the same tool or different ones. A session can talk to peers on this machine or on another machine you add as a peer hub. With the stop hook installed, a session that is idle when a message arrives is woken with the message already in hand. The [chat skill](/skills/aid-chat/) tells an agent how to use these commands.

```bash
aid chat node start                              # start this machine's hub
aid chat register --tool cursor                  # bind an identity; prints a minted <adjective>-<noun> name
aid chat hook --tool cursor --install            # install the stop hook that does the waking
aid chat roster                                  # who is available, across machines
aid chat open --channel pair                     # create and join a channel
aid chat connect --target green-giraffe          # pull a named peer into it
aid chat send --body 'ready when you are'        # say something
aid chat inbox                                   # read what arrived
aid chat ack --cursor 4                          # acknowledge up to a position
```

**Syntax:**

```
aid chat node start|stop|status [--port <n>]
aid chat register [--name <n>] --tool <host>     bind an identity for this directory
aid chat rename [--name <old>] --to <new>        rename mid-conversation; keeps the channel
aid chat open|join|leave [--name <n>] [--channel <c>]
aid chat list|roster [--name <n>]                channels here / who is available anywhere
aid chat connect [--name <n>] --target <peer>    pull a peer in; no accept step
aid chat send [--name <n>] --body <text> [--mention <p> | --whisper-to <p>]
aid chat inbox|ack [--name <n>] [--cursor <seq>]
aid chat subscribe [--name <n>] [--host-timeout <s>] [--follow]
aid chat heartbeat [--name <n>]                  keep this session from being reaped
aid chat hook --tool <claude-code|cursor> [--timeout <s>] [--check | --install | --uninstall] [--yes]
aid chat peers [--add|--remove --machine <host:port> | --discover]
aid chat show|audit|evict|retention|reap ...     operator surface
```

- `--name` is optional. When you leave it out, the node looks up the name registered for this directory and tool. If you set `AID_CHAT_SESSION`, that name is used. If two sessions of the same tool share a directory, the command lists the candidates and asks you to pass `--name`.
- `aid chat node start` listens on `127.0.0.1`, default port `8812`. It needs Node `22.13.0` or newer: without it the command exits with `9`. Starting a node that is already running exits with `8` and changes nothing.
- `aid chat hook` takes a `--timeout` of at least `10` seconds; the default is `60`. Without `--check`, `--install` or `--uninstall`, it prints the stop-hook block to paste.
- Exit code `14` means the node refused a well-formed request. The first word on stderr is the reason, for example `solo_channel`, `no_channel` or `already_in_channel`.
- Delivery is per-speaker first-in-first-out: every member sees one speaker's messages in the order that speaker sent them. Two speakers' messages have no promised order relative to each other.
- A message stays unacknowledged until you run `aid chat ack`, and an unacknowledged message is delivered again.
- A channel closes when its last member leaves, and its messages go with it.

:::caution[`aid chat hook --install` writes your host tool's settings]
It is the only AID command that writes a host tool's configuration. It writes user-scope settings only, merges into the existing file rather than overwriting it, takes a backup, refuses a settings file that git tracks, and asks before writing. `--uninstall` removes only AID's own entry. Running either again is safe.
:::

:::note[The operator verbs are not in the chat skill]
`show`, `audit`, `evict`, `retention`, `peers` and `reap` are marked as operator verbs in `aid chat -h`. The chat skill an agent reads does not describe them. That is not a security boundary: any session that can run shell commands can run the whole CLI.
:::

|------|-----------|---------|-------------|

| `--from-bundle <path>` | `add`, `update`, `update self` | — | Install offline from a local artifact. | `--dry-run` | `update`, `update self`, `update all`, `remove self` | off | Print what would happen and exit; change nothing. |
| `--verbose` | `add`, `update`, `remove`, `status`, `projects`, `dashboard` | off | Print per-file `Copied:` / `Up to date:` / `Updated:` / `Removed:` lines. |
| `--target <dir>` | `add`, `update`, `remove`, `status` | `.` (current folder) | Project root. It must exist, or the command exits with `2`. `update all` does not accept it. |

| `-Target <dir>` | `add`, `update`, `remove`, `status` | `.` (current folder) | Project root. |
| `-NoPath` | bootstrap (`install.ps1`), `remove self` | off | Skip PATH wiring or unwiring. |

## Exit codes

| Code | Meaning |
|------|---------|
| `0` | Success. "Nothing to do" is also success. |
| `1` | Generic runtime failure (extract failed, write failed), or a project whose format is newer than this CLI supports. |
| `2` | Usage error: unknown subcommand, bad argument, ambiguous tool, missing target directory, `--from-bundle` with `--version`. Also `aid add` on a project that still has the v3 layout (run `aid update` first), and `aid add` or `aid remove` while an upgrade is pending. |
| `3` | Network or fetch failure: the download or the latest-release lookup failed. Also `npm` or `pipx` missing during `update self` or `remove self`, and a dashboard server that failed to start. |
| `4` | Checksum mismatch: the SHA-256 of a downloaded file did not match `SHA256SUMS`. |
| `6` | No manifest: `remove` or `update` found no `.aid-manifest.json` (nothing installed). |
| `7` | `aid status`: the folder has a `.aid/` but no AID install. Also `aid dashboard start`: the dashboard server is missing from the install tree. |
| `8` | The dashboard, or the chat node, is already running. |
| `9` | The runtime for the dashboard is not on `PATH`, or the chat node needs a Node runtime that is missing. |
| `10` | `aid dashboard start --remote`: the tailnet exposure is unavailable. |
| `14` | `aid chat`: the node refused a well-formed request. |

## Environment variables

### User-facing

| Variable | Equivalent flag / effect |
|----------|--------------------------|
| `AID_TOOL` | The positional tool argument for `add`, `remove` and `update`. The bootstrap script also uses it to run `aid add` after installing. |
| `AID_VERSION` | `--version` |
| `AID_TARGET` | `--target` |
| `AID_FORCE` | `--force`. Set to `1` or `true`. |
| `AID_VERBOSE` | `--verbose`. Set to `1`. |
| `AID_NO_UPDATE_CHECK` | Set to `1` to turn off the update-available notice. |
| `AID_MIGRATE_YES` | Set to `1` to migrate every registered project after `aid update self` without asking. |
| `AID_HOME` | Override the global CLI install directory (default `~/.aid` on Unix, `%LOCALAPPDATA%\aid` on Windows). |
| `AID_NO_PATH` | Set to `1` to skip PATH wiring during bootstrap. |
| `AID_CHAT_SESSION` | The chat session name to use when you leave out `--name`. |

### Advanced and test hooks

| Variable | Effect |
|----------|--------|
| `AID_LIB_PATH` | Absolute path to a local `aid-install-core.sh`. It bypasses the remote fetch. |
| `AID_LIB_BASE` | Base URL for the remote lib fetch. |
| `AID_LIB_VERSION` | Pin the remote lib fetch to a release version. |
| `AID_SUMS_URL` | Override the URL of the `SHA256SUMS` verification file. |
| `AID_CLI_BUNDLE_URL` | Direct URL of the CLI bundle tarball. |
| `AID_CLI_BUNDLE_BASE` | Base URL for the CLI bundle fetch. |
| `AID_INSECURE_SKIP_LIB_VERIFY` | Set to `1` to skip the lib checksum check. **Insecure**: for test environments only. |

## Canonical tool IDs

| Tool ID | Agents folder | Root instruction files |
|---------|---------------|------------------------|
| `claude-code` | `.claude/agents/` | `AGENTS.md`, and `CLAUDE.md` (region) |
| `codex` | `.codex/agents/` | `AGENTS.md` |

## Tool auto-detect

When you run `aid add` without a tool name, the CLI looks for these markers in the project folder:

| Marker present | Detected tool |
|----------------|---------------|
| `.claude/` folder | `claude-code` |
| `.codex/` folder | `codex` |
| `.cursor/` folder | `cursor` |
| `.github/agents/` or `.github/skills/` folder | `copilot-cli` |
| `.agent/` folder | `antigravity` |

- Exactly one marker: that tool is used.
- No marker: an error with exit code `2`, `cannot auto-detect host tool; specify the tool explicitly (e.g. 'aid add <name>')`.
- More than one marker: an error with exit code `2`, `ambiguous host tool (found: X, Y)`, followed by the same advice.

## Install channels

To bootstrap the `aid` CLI itself, once per machine, see the [Installation guide](/guides/installation/). The channels and what each needs:

| Channel | Requires |
|---------|----------|
| `curl … \| bash` (Linux/macOS) | Bash |
| `irm … \| iex` (Windows) | PowerShell 5.1+ |
| `npm install -g aid-installer` | Node 22 or newer |
| `pipx install aid-installer` | Python 3.8 or newer |
| `--from-bundle` (offline, staging directory) | Bash or PowerShell 5.1+ |
