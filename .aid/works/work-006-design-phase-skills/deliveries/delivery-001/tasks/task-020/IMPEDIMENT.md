The contradiction is one of **scheduling**, not of implementation. task-020 § Scope
deliberately runs this oracle *"at the point where every feature-001 and feature-003 edit has
landed"* — and it is precisely feature-003's landed edits (nine skills, two `doc_set` entries)
that make the drift-check red. Clearing it requires writing
`site/src/content/docs/reference/{settings,skills}.md`, which the PLAN assigns to delivery-003
task-064 and which C-5 (one full render, never a partial) forbids here.

**This is not the failure AC-3 exists to detect.** AC-3's subject is *"the seed does not
move"* — no test script edited, no count-bearing assertion disturbed. All of that holds, in
full, and BLUEPRINT gate criterion 5's four conjuncts all pass (`EVIDENCE.md` §5). What is red
is a drift check over generated documentation content, which the conditional doc-set decision
did not touch.

**It also recurs downstream if unresolved.** delivery-003 task-062 re-asserts the same oracle
(`task-062/DETAIL.md:118`: *"`npx vitest run gen-reference` from `site/` passes"*) and is
ordered **before** task-064, the task that regenerates the pages.

## Options

### Option A: Narrow AC-3's vitest conjunct to what AC-3 is about
**Approach:** Read AC-3's vitest conjunct as *"the spec is unedited and its count-bearing
assertions are green"* — i.e. `git diff --exit-code -- site/scripts/__tests__/` clean plus the
five `toHaveLength` values unmoved plus the KB-doc-template test green — and evaluate
*whole-spec* green after task-064 regenerates the pages. Record the narrowing in feature-001's
Change Log the same way the AC-2 `find` narrowing (Q8) was recorded.
**Effort:** S
**Risk:** Low. Nothing is lost: whole-spec green is still asserted, one delivery later, by
task-062/task-064. The risk is bookkeeping — the narrowing must be written down, or a later
reader re-derives this same surprise a third time.
**Scope impact:** None on code. task-020's acceptance criterion is restated.
**Spec impact:** feature-001 SPEC AC-3 and §5 row 1 gain the same scoping sentence AC-3
already carries for its clean-diff conjunct (*"scoped to the suite scripts, never the files
under test"*) — the generated pages are files under test, by the identical argument.

### Option B: Move the regeneration of the two pages into delivery-001
**Approach:** Add a delivery-001 task that runs `node site/scripts/gen-reference.mjs` and
commits the two pages, so the spec is green at feature-001's close.
**Effort:** M
**Risk:** High. It splits a render across deliveries, which C-5 exists to forbid; it hands
delivery-001 a write on a tree PLAN.md's rw-sets say it neither reads nor writes, inviting a
write/write conflict with task-064; and the pages would go stale again the moment
delivery-002/003 add or rename anything, so the green would not survive to the gate.
**Scope impact:** Large — delivery-001 acquires a new resource and a new task.
**Spec impact:** PLAN.md rw-sets and the delivery-003 write sets change.

### Option C: Accept the red as a known, named deferral
**Approach:** Leave AC-3 as written, mark this conjunct explicitly deferred to delivery-003
task-064 in the delivery-001 gate record (the way row 10's `kb.html` conjunct already is), and
carry the finding forward.
**Effort:** S
**Risk:** Medium. It works, but it makes the delivery-001 gate carry a red oracle with an
explanation attached rather than a criterion that passes — and task-020's own criterion
*"exactly three conjuncts are deferred"* becomes four, which contradicts the criterion's
explicit count.

---

## Recommendation

**Option A.** It matches the reasoning AC-3 already applies to its sibling conjunct: the
clean-diff was deliberately scoped to *the suite scripts, never the files under test*, on the
ground that a diff over files this feature edits is *"unsatisfiable by construction"*. The
generated site pages are exactly that class — derived from inputs this delivery legitimately
changes — so the same scoping is the consistent reading rather than a concession. It also fixes
the recurrence in task-062 at the same time. Option C is the fallback if the SPEC is treated as
frozen, but it breaks task-020's own three-deferral count. The decision is the owner's.
