**Depends on:** task-090, task-091

**Scope:**
- **The census (feature-013 § D2).** The acceptance criterion is coverage *parity* with
  `/aid-summarize`, not any one suite, so this is a check performed at ship time: confirm that
  `/aid-graph`'s **preflight**, its **staleness behaviour** and its **artifact validation** each
  have at least one suite that fails when that behaviour breaks. The named suites are
  `test-graph-preflight.sh`, `test-graph-stale-check.sh`, `test-graph-read-only.sh`,
  `test-relationship-schema.sh`, `test-validate-relationships.sh`, `test-graph-gap-ledger.sh` and
  `test-graph-view-shell.sh`, plus feature-011's two contingent suites
  (`test-validate-html-profiles.sh`, `test-validate-visuals-profiles.sh`) if their contingencies
  fired.
- **The census reports what is there rather than asserting a number.** If neither contingency
  fired it covers five suites; if both did, seven. Both outcomes are correct, and the record must
  say which happened.
- **Where a behaviour has no failing-suite owner, raise the gap against the owning feature** --
  do not write the missing test here. A suite lives with the mechanism it proves; a test authored
  anywhere else goes stale the moment its subject changes, because its author is not the person
  editing the subject.
- **The coverage-parity gate.** Confirm `tests/coverage-parity.sh`'s before/after multiset
  inventory of executed assertion IDs records only net additions. It "fails mechanically on any
  un-excused net-removed/reduced assertion", and it matters here specifically because a plan that
  assumed feature-011's contingent suites must not leave a removal behind if those suites never
  landed.
- **The generated-catalogue read-back.** Confirm `site/src/content/docs/reference/skills.md`
  places `aid-graph` in the **Knowledge Base Maintenance** group with a description that reads as
  a complete one-paragraph summary beside `aid-summarize`'s. This is deliberately a *read-back*
  and not an edit: the page is generated by `site/scripts/gen-reference.mjs` from each skill's own
  `SKILL.md` `description`, so editing it would be reverted by the next build. If the entry does
  not read as a complete summary, **raise it against feature-010's `SKILL.md` frontmatter**, which
  is the file the generator actually reads.
- **Out of scope:** authoring any missing suite; editing the generated catalogue page; the
  `SKILL_GROUPS` roster entry and its `CURATED_SKILL_NAMES` mirror (feature-012, task-010); the
  registration suite itself (task-091); and the full HOME-pinned canonical-suite run (task-096).
