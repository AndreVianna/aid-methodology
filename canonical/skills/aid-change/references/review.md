# Independent review

Review the plan against the original request before building. Review each completed milestone against the repository and actual checks, then review the whole result against the request and repository. Check that relevant KB facts and project rules reached the checks and, for planned work, the plan; check that positive outcome evidence demonstrates the requested result rather than merely passing negative checks. Compare removed or replaced behavior and tests with the user needs that must remain; disclose missing or unexecuted checks. If the named reviewer returns an explicit unsupported or unrecognized model error and the user did not require that model, retry once with a separate independent reviewer using the host default and the same review task and criteria; disclose the fallback. Do not retry on quota, authentication, service or other errors; report them and stop if the required review cannot run.

For site or documentation changes, inspect the built result, cross-page consistency, accessibility and claims against current source. Check affected rendered pages for visible raw Markdown table separators and other broken formatting; distinguish intentional code examples from defects. Use an automated browser scan when available, then inspect reported pages; record the pages checked and leave unavailable or uninspected rendering unverified. A successful build or test count alone does not prove rendered quality.

For changed documentation pages, compare the reader-facing content before and after against the request and current source. Check that pages meant to teach a workflow still explain how to use it: headings, links or the absence of an error message alone do not establish useful coverage. Report missing or outdated material with the relevant page and source evidence; do not require retaining content the request intentionally removed.

For each finding, record the request text it misses, the repository fact and location it contradicts, or the failing check output. Only a finding supported by one of these blocks. Record whether the finding changed the result. Present other observations to the user without another review loop.

After one fix round, check the fixes and rerun affected checks. If a supported finding remains, stop and show the user its evidence; do not silently accept it or call the work complete.
